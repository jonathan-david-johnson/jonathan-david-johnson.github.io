My Tools

Agent skills and extensions I wrote to make agentic development repeatable instead of vibes. Some are tied to my harness; most are plain markdown that works anywhere.

Built for Pi

Pi is the coding agent I run day to day — an open, locally-configured harness installed as @earendil-works/pi-coding-agent. My entire config is a git repo, so the agent I use is versioned, reviewable, and reproducible on a new machine with one clone.

I use it because it gives me much tighter control than Claude Code or Codex. I choose the model per task rather than accepting a default, extend the agent itself in TypeScript, and decide exactly which skills load into context instead of paying for a fixed bundle. When I want different behavior, I write an extension — I'm not waiting on someone's roadmap.

choose-model Skill + extension · Python

Pick the right model for the job, with receipts.

Recommends a model for a given prompt from a persistent registry of costs, capabilities, and measured results — then lets you prove the recommendation. Evaluation is staged so scoring stays honest: fan out, test, score, record. Ships with a Pi extension (choose-model.ts) that exposes it as a slash command inside the agent.

  • run fans one prompt out to multiple models in isolated per-run git clones and writes a session manifest — no registry write yet.
  • set-score adjusts after hands-on testing; record commits the result to the registry.
  • Recorded runs keep the actual model output, so every score in the registry is auditable.
  • Pi-specific: the registry maps models to harnesses and the extension talks to Pi's model API directly.

pi extensions TypeScript

Changing what the agent does, not just what it's told.

Pi lets you register commands, tools, and UI directly in the harness. These are the ones I run every day — the reason I'd rather extend an open agent than work around a closed one.

  • skill-manager — searchable list of every skill, toggle what loads into context instead of paying for all of it.
  • model-thinking-picker — switch model and reasoning level mid-session, per task.
  • subagent — fan work out to isolated sub-agents, the same pattern the milestones use.
  • btw — spawn a side conversation in a subprocess so a tangent doesn't pollute the main context.
  • security-guard — intercepts destructive file and directory operations before they run.
  • caveman, ocr — terse output mode, and image OCR via tesseract.

Harness-agnostic skills

These are just markdown with a frontmatter description and a body of instructions. No harness API, no runtime — they work in Pi, Claude Code, or anything else that reads a skill file. Portability is the point: the workflow shouldn't die when I switch agents.

meta-repo Agent skill

One product, many platforms, no monorepo.

Scaffolds and extends a "monorepo shell": a top-level Makefile that delegates to per-platform nested git repos, with a docs/<platform>/ layout for milestones, bugs, and ADRs. Gives every agent the same map of the project no matter which platform it picks up.

  • Sets up a new platform, scaffolds its docs tree, and wires it into the top-level delegation targets.
  • Enforces the milestone and bug-doc conventions that planning agents read before writing code.
  • Same pattern I used to unify 30+ microservice repos at Disney — and the backbone of PocketRadio.

self-review Agent skill

Make the agent grade its own last run.

Reviews the last prompt, or a span of recent interactions, and extracts what actually went wrong into concrete improvements. The feedback loop that turns a bad session into a better skill file instead of a shrug.

  • Triggered by "review last run", "what went wrong", "lessons learned".
  • Produces actionable changes, not a postmortem essay.

html-doc Agent skill

Markdown in, presentable HTML out.

Converts any markdown document into two self-contained HTML views: a slide deck and a vertical-scroll page with sticky nav. A pure mechanical transform — it renders, it doesn't rewrite or editorialize.

  • Turns a design doc into something you can present without rebuilding it in slides.
  • Self-contained output — no build step, no external assets.

youtube-transcript Agent skill

Clean, timestamped transcripts, no API key.

Pulls a readable timestamped transcript out of a YouTube video using yt-dlp. Useful for turning a conference talk into something an agent can actually search and cite.

  • No API keys and no quota to manage.
  • Output is clean enough to feed straight into a summarization pass.
