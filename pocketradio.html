PocketRadio — Built by agents, planned by me

I forked Pocket Casts iOS and, working fully through coding agents, turned it into PocketRadio — a public-radio streaming + podcast app running natively on five surfaces, with two more planned. A meta-repo shell, docs-driven milestones, and planning agents that grill the plan before any code is written.

Meta-repo architecture

One product, five nested git repos under a shared shell. A single top-level Makefile delegates to each platform — checkout, status, build, test, run, deploy — so any agent can pick up any platform independently. The same discipline that unified 30+ microservices during my time at Disney.

Docs-driven milestones

Every platform keeps docs/<platform>/milestones/milestone_N.md, pointed at by a current_milestone.md symlink. Each milestone is written before code: a plain-language goal, a user-verifiable checkpoint, explicit scope, and a Behaviors to test list.

Planning agents, then fan-out

Milestones start as a grilling session — my planning skill, built on Matt Pocock's grill-me, interviews the plan branch-by-branch until decisions resolve. Then each behavior in the list fans out to its own sub-agent.

Remote play — the cross-platform milestone

Like Spotify Connect: keep listening on one device, control it from another, even across different networks. Devices announce themselves on a Supabase Realtime channel scoped to your Pocket Casts account and exchange play / pause / stop / load_station commands. No pairing step, nothing to configure — anything signed into the same account finds everything else.

Live between iOS (and CarPlay) and the macOS menubar today, currently one-directional: iOS sends, menubar executes. Bidirectional control, a device picker, and "Playing on {device}" indicators are the active docs/global/ milestone. Wire formats are pinned as JSON contract fixtures in contracts/remote/ so each platform's agent codes against the same spec instead of the other app's source.
